YOUR RAW FILE IS HIDING A JPEG

Photographers tend to assume a raw file is closer to the sensor and therefore closer to anonymous. It is the opposite. A raw file is the most talkative image file you own.

A raw file is a TIFF wearing a costume

DNG, CR2, NEF, ARW, ORF, RAF, PEF: different extensions, same skeleton. They open with a TIFF header and store their metadata in ordinary image file directories, the same structure a JPEG hides inside its EXIF block. Which is why a tool that can read EXIF can read a raw file without learning anything new.

What comes out is longer than a JPEG's list:

  • The camera body's serial number, and often the lens serial too. This is the single most linkable thing in photography: it ties every photo you have ever published to one physical object you own.
  • Your name, if you ever set the copyright or artist field in the camera menu, which most people do once and forget.
  • The original file name off the memory card, such as DSC_4821.NEF. Renaming your export does not remove it.
  • Maker notes: kilobytes of undocumented, vendor-specific camera internals. Shutter counts, focus data, sometimes serials again.
  • GPS, if the body or the grip had it.

The embedded JPEG

Here is the part that surprises people. Every raw file carries at least one fully rendered JPEG of the picture, so that your operating system, your camera's screen and your catalogue software have something to display without demosaicing anything.

That preview is a real image of your photo, and it survives everything you do to the raw data. Crop the raw in your editor and export a JPEG for the client: the raw file you archived still contains the uncropped view. Send that raw to someone and you have sent them the version you meant to crop out.

MetaStrip reports the previews with their real size and can blank them. It also uses one of them to show you the photo in the browser, since no browser can decode a raw file itself. It is the same trick your file manager uses.

Cleaning a raw without breaking your converter

Raw files cannot be cleaned the way an EXIF blob can. In a JPEG, MetaStrip can blank a whole directory entry, because that entry describes nothing the picture needs. In a raw file the same directory holds the structural tags: image width, image height, where the strips of sensor data actually live. Blank those and Lightroom or Capture One will not open the file.

So raw removal blanks values in place and leaves every entry header standing, which keeps the directories sorted and the structural tags pointing where they always did. The test suite checks exactly that: image width and image height survive a strip byte for byte, and the directory keeps its entry count.

Nothing is re-encoded, no sensor data is touched, and the file is the same size it was. Your converter opens it exactly as before. It just no longer knows your name.
